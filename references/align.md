# Align — 澄清意图的访谈协议（Stage 0）

目的：在 Discover 之前，用多轮 QA 把"用户想要什么"从一句模糊的中文短句
变成一份可执行的设计 brief——让 agent 和用户在动手之前达成共识。

## 何时跳过这一步

- 用户已经给出完整的 brief（内容/受众/形式/风格参考全齐）；
- 用户明确说"直接做，别问我"。

其余情况默认执行 Stage 0。轮数通常 2–3 轮（每轮 2–4 个问题），
超过 5 轮说明问题设计有问题——你在浪费用户的耐心而不是澄清意图。

## 第 0 步：能力探测（在任何设计问题之前运行）

运行 `references/tools/capabilities.mjs`，向用户展示本机实际可用的
能力清单。这一步决定概念门的天花板——在不知道能做什么之前设计方向，
等于在设计一个可能做不出来的方案。

探针输出六项能力：图像生成、视频生成、文生 3D、图像超清、本地绿幕
抠图、本地 AI 抠图（rembg）。

**向用户呈现结果并主动推荐**：

- ✓ 可用的能力 → 简要说明"这意味着概念可以包含 XX 类效果"；
- ✗ 缺失的能力 → 按项目需求判断是否关键：关键的，给出安装/配置命令
  并**辅助用户完成安装**（如 `pip install "rembg[cpu]"`、`npm i -g
  lighthouse axe-cli svgo`、`winget install BlenderFoundation.Blender`）；
  非关键的，在 brief 中标注"本 run 不涉及"；
- 将探针结果写入 PROJECT-BRIEF.md 的 `capabilities` 字段，概念天花板
  门以此为据。

**设计期望管理**：向用户说明缺失能力的影响——"没有视频生成 key，
深潜页面在午夜层将以程序化生物剪影代替实拍级水母"。不要沉默降级。

## 设计树方法

把"用户想要什么"映射成一棵**设计树**：每个决策分叉出挂在它下面的
决策。每轮只问**前沿**（frontier）——前置条件已确定、现在就能问的
问题。每轮把整个前沿一次问完，编号 + 给推荐答案，然后等用户回答。

```
❓ **Q1** - **<问题标题>**: <问题正文，可多段，可含选项>

➡️ <推荐答案>

---

❓ **Q2** - **<问题标题>**: <问题正文>

➡️ <推荐答案>
```

规则：

- **事实自己查，决策问用户**。需要环境信息（文件、素材、品牌资料）
  就自己派子代理去找，不要问用户能自己查到的东西；
- 每轮回答会重塑树：已定的决策把前沿向外推，解锁依赖它们的问题；
- 本轮内还有依赖的问题属于**下一轮**，不属于这一轮；
- 前沿清空 = 访谈结束。**用户确认达成共识之前不动手**。

## 必问的四个问题（缺什么问什么）

1. **受众与场景**：这个作品给谁看，在什么场景下看？（手机上刷到的？
   投影演示？印刷品？）
2. **核心信息**：三秒后用户应该记住什么？（一句话）
3. **审美方向**：有没有参考——喜欢的站点、品牌、时代感、情绪？
   （"没有，帮我发散"也是合法答案，但必须问）
4. **交付形态**：网页 / App 屏幕 / 幻灯片 / 海报 / 沉浸 3D——用户
   没指定时给推荐并说明理由。

## 可选的第五问：评审模型

问用户是否为评审角色指定一个设计能力更强的模型（推荐），或用当前
会话模型。这个决定影响 Define 阶段的天花板。

## 方向卡先给用户挑（可选但推荐）

Brief 定了之后、正式进入 Discover 之前，可以给用户看 3–4 张**简化
方向卡**（各一段话：形式语言 + 配色气质 + 签名元素），让用户先排除
明显不想要的——这比完整 Discover 之后才发现方向错了便宜得多。

## 产出：PROJECT-BRIEF.md

访谈结束后写一份一页纸 brief，包含：受众与场景、核心信息、审美
方向（含参考）、交付形态、评审模型选择、用户排除的方向。这份文件
是后续所有阶段的输入——Discover 的问题简报从这里出发，评分表在
这里预填，方向卡在这里核对。

用户确认 brief 之后才进入 Stage 1 Discover。
